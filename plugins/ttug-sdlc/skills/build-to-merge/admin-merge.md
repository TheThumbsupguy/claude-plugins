# Admin merge

**`admin`** on the call (`/ttug-sdlc:build-to-merge reviews 3 admin <scope>`) is the owner's word for an admin merge on this run's PR, given up front. A repo allows admin merges only with an `Admin merge:` line in its repo file that names at least one required check (`Admin merge: allowed on <owner>'s word · required checks: <name>, <name>`). Without that line `admin` is ignored: say so in one line at the start and run as if it were not on the call. With it, `admin` is either/or: step 8 merges with `--admin` and never tries a normal merge first; without `admin`, step 8 tries only a normal merge, and a refusal is a stop. Where the repo file's merge fence names the owner's admin word as a release, `admin` on the call is that word; it lifts no other fence, no failed check and not `ask`. The PR body's mode line says which (SKILL.md, PR body). That line is a record only: a resumed run (a compaction, a new session) gets `--admin` only from the owner's word, given again.

Never `--admin` unless the repo file has an `Admin merge:` line and the owner said so for this PR: `admin` on the call, or their word for this PR given during the run (after a refusal, as a merge-fence release, or again on a resumed run); from then on step 8 is either/or as with `admin`. Nothing else on the call counts as that word. Before any `--admin`, every check that line names, and every row of `gh pr checks <PR> --required`, must read `pass` in `gh pr checks <PR> --json name,bucket`; missing, pending or skipping is not passed. Read `headRefOid` at the same time and merge with `--match-head-commit <sha>`.
